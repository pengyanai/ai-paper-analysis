# Agent-Reflex：别再假设工具永远可靠，教智能体在噪声里学会"回过神来"

你有没有遇到过这种情况——精心调出来的 Agent 在测试环境里跑得顺风顺水，一上线就原形毕露：MCP 服务时不时 502、工具返回超时、用户中途插一句"不对，我要的是另一个"，然后 Agent 要么死磕重试，要么直接跑偏，再也拉不回来。

人大高瓴团队这篇 Agent-Reflex（arXiv 2610.17953）就是冲着这个痛点来的。说实话我第一反应是"又是一篇反思机制的论文吧"，但读完之后发现它的切入点比 Reflexion 那一系要扎实得多：**它把"反思"当成一种可以从真实失败中挖掘、监督、内化的元技能，而不是推理时临时拼凑的自我批评**。

**核心摘要**：现有 Agent 训练环境有个理想化假设——工具反馈干净、用户不干预。这篇论文先实证了这个假设有多离谱（GPT-5.2 在工具噪声下成功率掉 10 个点以上），然后提出三阶段框架：RSD 从 24,510 条真实工具错误中提炼出 8 类故障家族，注入 557 个 MCP 可执行环境，用 9 个模型的轨迹对比挖出 1,170 条反思元技能；ReSFT 把技能转成三种可验证的监督数据（自我反思/全局恢复/用户纠正）；ORPO 再在噪声 RL 上叠加技能引导的 on-policy 蒸馏。基于 Qwen3-8B，五个长程工具基准总分 58.6，AgentNoiseBench 上 29.1，全面压过环境扩展和反思类 baseline。我的判断：这不是底层理论突破，但**从"真实错误挖掘技能库"到"技能做特权教师"这条链路是目前所见反思训练里最工程化、最完整的一条**，值得做 Agent 训练的同学细读。

## 🎯 问题动机：两个被假装不存在的现实

这篇论文最有说服力的部分不在方法，在它开篇摆出来的证据。Figure 1 把问题拆得明明白白：

![图1：从理想化交互到反思式恢复](https://arxiv.org/html/2610.17953v1/fig1_motivation_compact.png)

*图1：(a) 以往训练环境假设固定任务+干净反馈；(b) 真实部署中用户会多轮纠正、工具会返回超时和服务不可用；(c) GPT-5.2 和 Claude-4.5-Sonnet 在无噪声/用户噪声/工具噪声下的成功率；(d) 从 24,510 条真实工具错误返回中挖出的 8 类故障分布。*

看 (c) 这组柱状图挺扎心的：GPT-5.2 在 Airline 场景无噪声时成功率约 80%，加上工具噪声掉到 65% 左右，Delivery 场景从 65% 掉到 50% 附近。Claude-4.5-Sonnet 同样全线缩水。**最强的前沿模型都扛不住噪声，这说明问题不在模型规模，在训练分布。**

再看 (d)：作者回放了 9 个公开 Agent 基准上的工具调用，收集 177,700 条工具返回，其中 24,510 条是错误。归类后 8 个故障家族——服务不可用占 33.6%，认证/权限失败 17.9%，超时 14.7%，资源不存在 10.5%，参数校验失败 10.2%……这不是拍脑袋合成的噪声，是从真实生产级 MCP 生态里统计出来的。

顺着这个再聊一层：为什么 Reflexion、Self-Refine 这类推理时反思不够用？论文给的诊断我觉得很准——**批评信号来自那个已经失败的策略本身**。一个格式良好但内容错误的工具返回，模型自己很难反驳自己。而训练时的方法（Agent-R、ReflectRL、NoisyAgent）虽然把纠错信号搬进了参数，但学的是单条轨迹的修复，没有任何东西沉淀成"这个环境的恢复规则"供后续 episode 复用。

这就是 Agent-Reflex 要填的缝：**把失败经验提炼成环境级别的、可复用的元技能库**。

## 🏗️ 方法核心：三阶段，从挖矿到内化

![图2：RSD 与 ReSFT 流水线](https://arxiv.org/html/2610.17953v1/figure2_final.png)

*图2：Stage 1（上）从 557 个 MCP 锚定的可执行环境出发，注入挖出来的故障家族，用 LLM Agent Pool 跑出成败轨迹对，提炼离线技能库；Stage 2（下）从技能库采样 SR/KR/UR 三种修复延续，只保留通过验证器的样本，且存储时剥掉技能提示。*

### Stage 1：RSD——从真实错误里挖技能

一句话版：先造一批"会出错"的逼真环境，再让一群能力各异的模型去踩坑，最后从"别人成功了它失败了"的对比里提炼出恢复规则。

细节上有几个设计我觉得值得说。

**环境不是合成的，是 MCP 锚定的。** 选了 Smithery 注册表里按使用量排名的 557 个高频 MCP server，沿用 Agent-World 的套路：研究 Agent（GPT-OSS-120B）围绕主题建数据库并做 3 轮复杂化扩展，编码 Agent 生成工具和单测，只保留能编译、过测试、满足状态转移约束、支持可执行验证的工具。每个环境配 60 个可验证任务。

**噪声不是编的，是统计的。** 注入概率 $p_{\mathrm{inj}}=0.2$，每个工具返回位置独立地以伯努利采样决定是否替换为故障：

$$o_{t+1}^{\mathrm{train}} = \begin{cases} J(o_{t+1}), & b_{t+1}^{\mathrm{inj}}=1 \\ o_{t+1}, & b_{t+1}^{\mathrm{inj}}=0 \end{cases}, \quad b_{t+1}^{\mathrm{inj}} \sim \mathrm{Bernoulli}(p_{\mathrm{inj}})$$

注意一个细节：故障家族是按均匀分布抽的，而不是按真实频率——否则占比 0.3% 的网络连接错误就永远学不到恢复策略。这个平衡采样的小决定其实很关键。

**技能来自跨模型对比，不是单模型自省。** 轨迹采样池有 9 个模型、5 个家族，从 Qwen3-4B 到 DeepSeek-V4-Flash（284B）。同一任务下，有的模型成了、有的败了，分析器（DeepSeek-V4-Flash）对比成败对，识别复发性失败模式，转成结构化技能记录：触发条件、诊断（属于哪个故障家族）、恢复模板（何时重试/换端点/问用户/放弃）、可逆性标记。最终在 557 个环境上沉淀出 1,170 条元技能。

这里有个容易被忽略但很重要的公平性声明：**训练轨迹全部来自 Qwen3-8B 自己**，多样化的模型池只用于挖掘行为对比，更强的模型只当分析器。也就是说 8B 策略没有偷师大模型的轨迹，和 baseline 的比较是干净的。

### Stage 2：ReSFT——三种姿势把技能变成监督

技能库躺在那里不会自己变成能力。ReSFT 设计了三种可验证的采样策略，对应三种修复场景：

| 策略 | 修复粒度 | 做法 | 存储的输入 |
|------|---------|------|-----------|
| SR（自我反思） | 局部修复 | 环境回滚到首个错误步 $t^\star$ 前的状态，拼接技能 $\kappa$ 继续生成 | 去掉技能，只留历史 |
| KR（技能恢复） | 全局重启 | 回到初始状态，带着技能从头重做整个任务 | 去掉技能，只留任务 |
| UR（用户中心反思） | 用户纠正 | 用户模拟器把技能改写成自然语言纠正 $u_\kappa$，插入错误步后继续 | 保留用户消息，技能不进上下文 |

关键设计是**特权信息剥离**：技能 $\kappa$ 只在采样时当"作弊提示"引导模型走出正确修复路径，存进训练集时删掉。策略学到的是"在没有提示的情况下自己回过神来"，而不是"看到提示才会修复"。所有样本必须通过环境验证器——能真正把任务救回来的才留下。最终语料 54K 条轨迹。

还有个小心思：UR 的用户模拟器（GPT-4.1）被刻意要求覆盖直接纠正、部分提示、模糊表述、甚至**故意错误的建议**——因为现实中用户的话不是圣旨，盲服从也是病。

### Stage 3：ORPO——技能当特权教师的 on-policy 蒸馏

这是全文技术上最新颖的一块，Figure 3 画得很清楚：

![图3：ORPO 框架](https://arxiv.org/html/2610.17953v1/Figure3_new.png)

*图3：一次更新中，G=8 条轨迹组成混合组（25% 在扰动环境中 rollout），共享组内归一化优势进 RL Loss；同一批 action token 再在"拼上技能卡"的上下文下重打分，detach 后的技能诱导偏移经 sigmoid 置信门控，产出 OPD Loss。*

先说 RL 侧。每个任务采样 $G=8$ 条轨迹，比例 $\nu=0.25$ 跑在扰动环境里，其余跑干净环境。**优势在整个混合组上归一化**（GRPO 式），而不是干净/扰动各自归一：

$$\widehat{A}_{q,i} = \frac{R_{q,i} - \mu_q}{\sigma_q + \epsilon}$$

为什么混着归一？论文的解释是：分开归一会让失败轨迹自成一派形成独立对比，混在一起则把真实失败留在 on-policy 分布内部。这个选择我觉得有道理但论文没给消融，算个小疑点。

再说 OPD 侧，这是 ORPO 的灵魂。同一个 policy，对已经采样出来的 action token，分别在普通上下文和拼上技能卡的上下文下打分：

$$\Delta_{q,i,t,k} = \mathrm{sg}\left[\ell^{\mathrm{skill}}_{q,i,t,k} - \ell^{\theta}_{q,i,t,k}\right], \quad \gamma_{q,i,t,k} = \mathrm{sigmoid}(\beta_{\mathrm{opd}} \Delta_{q,i,t,k})$$

$$\mathcal{L}_{\mathrm{OPD}}(\theta) = \mathbb{E}\left[\chi \cdot \gamma \cdot \left(\mathrm{sg}[\ell^{\mathrm{skill}}] - \ell^{\theta}\right)\right]$$

直觉上：如果某个 token 在"看了技能提示"之后概率明显变高（$\Delta > 0$），说明这个 token 正是技能能教会策略的反思决策点，就给它更大的权重把概率推上去；如果技能提示帮不上忙甚至帮倒忙，权重压小。教师分支只前向、不回传梯度、不查环境——**额外成本就是一次前向，不是一次 rollout**，这个账算得很划算。

这套 OPD 框架借自 SEED（Wu et al., 2026），区别在特权上下文是什么：SEED 用的是别的信号源，ORPO 用的是 RSD 挖出来的、按环境索引的技能卡。技能查找不做语义检索——每个 RL 任务自带环境 ID，直接 `Lookup(env_id(q), K)` 拿到技能卡。推理时技能提示移除，部署的策略不需要技能库。

## 📊 实验：数字说话

### 主实验：五个长程工具基准

评测组合：BFCL-v4、ACEBench、ToolSandbox（200 个分层任务）、τ²-Bench、VitaBench，全部统一从 Qwen3-8B 出发训练。挑几个关键数字：

| 方法 | VitaBench Avg. | τ²-Bench Avg. | BFCL V4 Avg. | ACEBench Avg. | ToolSandbox | **Overall** |
|------|------|------|------|------|------|------|
| Qwen3-8B（基座） | 11.4 | 26.2 | 77.2 | 54.0 | 40.2 | 40.2 |
| Reflexion-8B | 6.8 | 34.5 | 72.1 | 64.0 | 44.7 | 44.7 |
| Agent-R-8B* | 7.3 | 30.6 | 74.7 | 50.0 | 40.1 | 40.1 |
| NoisyAgent-8B* | 15.3 | 42.8 | 74.6 | 52.0 | 43.4 | 43.4 |
| EnvScaler-8B | 15.8 | 37.9 | 74.6 | 72.5 | 50.9 | 50.9 |
| Agent-World-8B* | 14.5 | 54.6 | 80.2 | 72.0 | 53.6 | 53.6 |
| **Agent-Reflex-8B** | **17.5** | **62.1** | **81.4** | **78.0** | **58.6** | **58.6** |

几个观察：

**τ²-Bench 上 62.1 vs Agent-World 的 54.6**，7.5 个点的差距在同池对比里很能说明问题——Agent-World 是它的环境构建方法的前作，覆盖度一致的情况下差距只能归因于反思监督本身。ACEBench 上 78.0 vs NoisyAgent 的 52.0，涨了 26 个点，说明环境级元技能确实比单轨迹纠错和纯噪声暴露更有料。

不过要泼点冷水：VitaBench 上 17.5 的绝对值依然很低（GPT-5.2 也才 37.7），这类生活化长程任务对 8B 模型本来就很难，Agent-Reflex 赢在相对优势，别误读成"解决了"。

### 噪声鲁棒性：AgentNoiseBench

| 方法 | ANB-τ² Avg. | ANB-Vita Avg. | **Overall** |
|------|------|------|------|
| Qwen3-8B | 20.2 | 4.4 | 12.3 |
| EnvScaler-8B | 27.1 | 9.3 | 18.2 |
| NoisyAgent-8B | 37.6 | 14.2 | 25.9 |
| **Agent-Reflex-8B** | **45.9** | **12.3** | **29.1** |

论文特意强调 AgentNoiseBench 对它是**完全 OOD** 的：噪声分类法、注入器、环境都没在训练中见过。这点的确增加了说服力。但也要注意到 ANB-Vita 上 12.3 其实没超过 NoisyAgent 的 14.2，Overall 领先主要靠 τ² 侧 45.9 的大幅优势。说"全面碾压"是不准确的。

附录 E.1 的细粒度分析反而是我最喜欢的实验。用 Stability-Gated Success（轨迹没被带偏且任务答对才计分，排除"被带偏但蒙对"的水份）按 13 个噪声轴拆开看：工具侧领先最大的是 misleading lure（13.9，归一化后）——就是那种**格式完全合法但内容在撒谎**的返回，schema 校验抓不到，只能靠 payload 里的证据发现。这正是 RSD 独有的贡献：更多的干净环境只会增加成功轨迹，永远不会告诉你"哪条看似正常的返回其实骗了你"。整体被带偏率：Agent-Reflex 28.5%，EnvScaler 44.8%，基座 56.1%。

### 消融：谁在扛大梁

| 变体 | ANB-τ² | ANB-Vita |
|------|------|------|
| 完整 Agent-Reflex | 45.9 | 12.3 |
| 去掉 SR（自我反思） | 41.3 | 8.9 |
| 去掉 KR（全局恢复） | 42.4 | 10.2 |
| 去掉 UR（用户纠正） | 43.0 | 10.9 |
| 去掉 OPD | 43.7 | 9.5 |
| 去掉置信权重 | 44.5 | 10.4 |

排序很一致：SR > KR > UR > OPD。**局部失败感知和修复是反思行为的地基**，全局重启次之，用户纠正再次。另一个重要结论是：技能库光存在不够——去掉 OPD 的 token 级蒸馏明显掉分，只去掉置信权重也掉。收益来自蒸馏信号本身，不是技能暴露。消融做得干净，每个组件都 load-bearing，没有凑数的。

### RL 算法对比

Figure 4 里从 Qwen3-8B 出发、同一 2.5K EnvScaler 任务池、100 步 RL、匹配预算，ORPO 稳定压过 GRPO、DAPO、REINFORCE++，也压过同样带 OPD 信号的 SEED 和 NoisyAgent RL。训练曲线上 ORPO 在 GRPO 和 SEED 已经走平之后还在涨。作者归因于置信权重让技能无关的 token 不主导更新——机制上说得通，虽然 100 步的对比规模偏小，长期行为还得再观察。

## 🤔 我的判断

**值钱的地方：**

一是**噪声的实证基础**。24,510 条真实工具错误统计出的故障分类学，比拍脑袋合成噪声的所有工作都更接地。这个分类学和注入器开源后，本身就能成为社区资产。

二是**特权信息蒸馏的完整闭环**。技能只在训练时当教师、推理时完全剥离，部署零额外成本。SR/KR/UR 三分法把"反思"这个含糊概念拆成了可操作、可验证、可消融的监督信号。这种"把模糊能力结构化"的功夫，比单点 trick 更有方法论价值。

三是**公平性控制的自觉**。训练轨迹全来自 8B 基座、强模型只当分析器、ORPO 直接复用 EnvScaler 的 RL 任务池以便归因——这些声明说明作者知道审稿人和读者会挑什么刺。

**要警惕的地方：**

技能库是离线快照，工具接口变了就得重新挖（作者在 Limitations 里承认了）。1,170 条技能对 557 个环境，平均每个环境两条多一点，覆盖密度其实不高。另外 ANB-Vita 上输给 NoisyAgent 这件事论文没有深入讨论，用户噪声场景下的天花板还在。混合组归一化这个关键设计选择也没给消融。

和同期工作比，它站在了 Agent-World（环境合成）+ SEED（OPD 框架）的肩膀上，增量在"技能挖掘"和"反思监督结构化"这两层。不是从 0 到 1，但从 1 到 10 的工程整合做得相当漂亮。

**工程启发**：如果你在搭 Agent 训练管线，有三件事可以直接抄——① 先统计你生产环境里真实的工具错误分布，别合成假噪声；② 用回滚环境状态+特权提示采样修复轨迹、存库时剥提示，这个套路通用性很强；③ 教师分支只前向的 OPD 成本极低，值得加进任何 agentic RL 里试试。
